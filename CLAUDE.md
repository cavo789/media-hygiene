# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`media-hygiene` finds and safely cleans duplicate photos and videos across folders and disks. It
was called `media-dedup` up to 0.2; what remains of that name is deliberate:
`MEDIA_DEDUP_*` variables are no longer read (0.4.0), `summary.json` accepts
`only_media_dedup`, `tests/fixtures/0.2.0/` proves old files still load, and the devcontainer
volumes keep their names. It ships as a Docker image published on Docker Hub as `cavo789/media-hygiene` (amd64 + arm64, by CI
on a `vX.Y.Z` tag that the helper `release` creates; local build: `docker build --tag
media-hygiene .` (the default, last target `local` names itself in the commands it suggests; CI
pushes `--target published`), `ENTRYPOINT ["media-hygiene"]`) run from PowerShell or WSL; the image builds a minimal `ffprobe` and `ffmpeg` from pinned sources. User documentation:
[README.md](README.md) / [README_FR.md](README_FR.md) (quick start + contents only) and
`documentation/en/` / `documentation/fr/` (same file names and `images/` in both). Step by step,
one guide per goal after shared first steps: `start/` (steps 1–3: audit, cache, several folders),
then `clean/` (steps 4–15) or `sort/` (from step 4, with `classify`); `commands/` holds one page
per CLI verb (what it does, mounts, options, examples, its `--help` capture), indexed by
`reference-commands.md` — a new verb needs its page in both languages and its name in
`COMMANDS_TOO` of `tests/support/docs/scenario.py` (`tests/unit/test_docs_commands.py` checks
it), its entry in `cli/menu_catalog_*.py` (the actions `mh menu` and the home page list;
`tests/unit/test_menu_catalog.py` checks it) and in `nav` of `.config/mkdocs/mkdocs.yml`, the site the CLI links to (GitHub Pages,
`docs.yml`; `tests/unit/test_docs_site.py`); reference pages and the developer page stay at the root of each language — **update both
languages with every user-facing change**; `tests/unit/test_documentation.py` checks links,
anchors, parity and unused screenshots. Screenshots and `<!-- capture: … -->` console blocks are regenerated by
`docs_screenshots` (`tests/support/docs/`: synthetic pictures only, never real photos; the rest
of each page is hand-written).

Converse with the user in French; code, comments, docstrings and TODO files are in English.

## Architecture (`src/media_hygiene/`)

Data flows `scan` → `plan` → `actions` → `report`, orchestrated by `services`, exposed by `cli`.

| Package | Role |
|---|---|
| `cli/` | Typer commands (`audit`, `crosscheck`, `review`, `clean`, `undo`, `history`, `reports`, `purge`, `inventory`, `config`, `classify`, `review-sort`, `sort`, `places`); thin: build a settings layer, call a service, display. `cli/app.py` builds the app **after** the locale is installed (`__main__.py`). |
| `services/` | Use cases: `AuditService`, `CleanService`, `cross_check`, `serve_review`, `undo_run`, `write_report`; `Runtime` bundles settings, locations, mount table, output. |
| `scan/` | `walker` (os.scandir; lists what it could not read), `exact` (size → partial SHA-256 → full SHA-256), `broken` + `file_check` (Pillow decode in a process pool, `ffprobe` for videos); the same decode yields `VisualFacts` (`visual`: dHash, pHash, Laplacian sharpness with numpy, EXIF date and camera) and a versioned `MediaMetadata` (`exif`, `gps`, `jpeg_quality`, `exposure`; `video_meta` from the same probe): facts only, never judgments; `inventory` counts them. `video_prints` fingerprints each readable video once (`keyframes`: `ffmpeg` decodes frames at 10–90 % of its length, hashed as images; `tool_run` runs `ffprobe`/`ffmpeg` with a time limit). Pure asyncio (`TaskGroup`, semaphore). |
| `index/` | SQLite cache of digests/integrity/visual facts/metadata/video fingerprints (`video_rows`, schema 5) keyed by (path, size, mtime) → incremental audits; `schema` upgrades older index files in place (metadata then read once, from image headers); `pruning`: the audit forgets the files a walk proves gone, `clean` those it removed. |
| `plan/` | `KeepPolicy` (protected > preferred > has a sidecar > not a copy name > name not generated by a device/app > folder not generic > oldest > shortest path > alphabetical; the decisive criterion is recorded as `KeepReason`) and `build_plan`; `similar` finds burst series (`bursts`, listed only) then near duplicates (`near`, multi-index hashing) and re-encoded videos (`near_video`: same length, proportions and frames, same date or none); `likeness` holds the shared hash distances; `clean --tier near` quarantines both, never deletes. |
| `crosscheck/` | Second opinion: the `jlesage/czkawka` command the audit prints (same mounts, extensions, exclusions) and the group-by-group comparison with its JSON results, out-of-scope files set aside. |
| `actions/` | Write-ahead JSONL journal (`pending` then `done`), `CleanExecutor` (byte compare before delete, verified quarantine move), `UndoExecutor` (rebuild from keeper / quarantine), purge, run history. |
| `review/` | `media-hygiene review`: burst series one at a time in the browser, keyboard driven. Minimal HTTP/1.1 on asyncio streams (loopback `Host` only, JSON-only `POST`), a session saving `decisions.json` (`bursts` key, next to the report's `pairs`) at each choice; `clean --decisions` quarantines the shots set aside. `media-hygiene review-sort` (`sort_*.py`): the events of a classify plan one at a time, choices saved in `sort-decisions.json` next to `plan.json` with the workbook value each one saw (`base`); `classify/page_overlay` lays them over the workbook's edits for `sort` and the carry-over (a later workbook edit of the same event/file is a conflict, never settled silently). `pick_*` templates: the one grid of photos to pick (gestures, keys panel, bar, large view) of `browse` and `search` — skill `photo-picking-pages`. |
| `geo/` | Offline geography: haversine distances, a one-degree grid nearest-neighbour index (numpy), `Gazetteer` over the vendored GeoNames snapshot `geo/data/` (CC BY 4.0, `ATTRIBUTION.txt`; rebuilt by `geonames_update` from `tests/support/geonames/`); `areas` (point in polygon, holes, multipolygons); `nominatim` (opt-in search of an area by a typed name, from `places` only: 1 request/s, identifying User-Agent, session cache; `[places] nominatim_url`, empty disables it); `landmarks` (offline monuments, castles, churches… of GeoNames, 0472); `reverse` (0474: an `import` names its new photos' rounded spots online, cached in `/cache/place-names.json`). No position ever leaves the machine without the user's explicit Yes, asked each time (`[places] reverse_lookup`). |
| `places/` | `media-hygiene places`: a Leaflet map (vendored, BSD-2, `places/static/`) of the index's GPS clusters, served like `review` (loopback `Host`, JSON-only `POST`, CSP allowing the `[places] tiles` host only); saves `[[classify.places]]` (a circle, or an OSM `area` + `osm` id) into `config.toml` with tomlkit (comments kept, atomic); `POST /api/osm` asks Nominatim server-side (`osm_search`). The `place`/`trip` rules live in `classify/whereabouts.py`, `place_match.py`, `trips.py`, `trip_walk.py`. |
| `docs/` | The documentation inside the image (0270): `render` (+ `nav`, `rewrite`; build time only, `docs` dependency group, a default group with `dev`: the image's builder uses `--no-default-groups`) turns `documentation/` into one fragment per page, its screenshots and an `index.json` per language with the site's extensions and anchors (`links`, loaded by path by `.config/mkdocs/hooks.py` too); the `docs` stage of the Dockerfile writes them to `/usr/share/media-hygiene/docs`; `shelf` finds them (`MEDIA_HYGIENE_DOCS_DIR`: rendered from the sources, the `hygiene` helper sets it); every page's server answers `/docs/` (`review/shared_routes`, `review/docs_app`, `view` in the home page's shell); `served_url`: a chapter served here, else the public site (the terminal and the reports keep the site). |
| `report/` | Self-contained Jinja2 HTML reports (+ previews, one page per folder pair, `plan.csv`, `summary.json`, `index.html`); `inventory.xlsx`/`.csv` streamed from the index alone (`index/listing`). |
| `config/` | Frozen pydantic `Settings`; layers file (`config.toml`) < env (`MEDIA_HYGIENE_<SECTION>__<KEY>`) < CLI. |
| `paths/` | Mount points (`Locations`, each overridable by `MEDIA_HYGIENE_<NAME>_DIR`), mount table, `/data/c/x` ↔ `C:\x` mapping. |
| `i18n/` | gettext: `_()`/`ngettext()`, `.po` catalogs loaded at runtime with polib (no `.mo` in the repo). |
| `console/` | Rich output facade (tips 💡), progress bars, tables, logging. |

Mount points: `/data/<drive>/<path>` (folders to scan), `/config` (config.toml **only**),
`/journal`, `/quarantine`, `/reports`, `/cache`. Never store other data under `/config`, but
`/config/people/<name>.toml`: the face lists of each person named, linked from `config.toml`
(0300). Only
the quarantine goes per drive: `/quarantine/<x>` (`X:\media-hygiene\quarantine`, mounted by
`mh` for each photo drive but `C:`) receives the files of drive `X:` (`paths/quarantines.py`,
`QuarantineRoute`); `/quarantine` is `C:`'s and the default; readers list every quarantine and
skip the one-letter folders; `undo`/`purge <run>` refuse a run whose drive quarantine is not
mounted (`purge` alone keeps such runs).

Semantics to preserve: `protected` folders are never modified and always hold the kept copy (so
identical files elsewhere are deleted); `excluded` folders are not analysed (a real backup).
`clean` refuses to run without a persistent `/journal` or on `:ro` data mounts.

## Commands (devcontainer helpers — never a Makefile)

The devcontainer prints a cheatsheet in every terminal (`.devcontainer/scripts/interactive.sh`
+ `helpers/*.sh`, functions annotated `# @cat` / `# @cmd` / `# @desc`, exported in
`interactive.sh`). Add new developer commands there.

```bash
check                 # lint, then pytest --cov — every heavy helper runs gently (nice, half the CPUs; DEV_CPUS=n)
lint                  # pre-commit only (ruff, mypy, pylint src+tests, shellcheck, shfmt, hadolint), new files included
format                # ruff format + ruff check --fix
tests [pytest args]   # e.g. tests tests/unit/test_keeper.py -k preferred
tests_quick [args]    # only the tests importing the files changed (TESTS_DEPTH=1 widens; .claude/scripts/tests_for.py)
e2e                   # build media-hygiene:latest, then pytest -m e2e (real docker run; log in /tmp/media-hygiene/e2e.log)
hygiene <command>     # run the CLI from sources against /tmp/media-hygiene/*
demo / demo_clean     # sample tree in /tmp/media-hygiene/data, then audit / empty /tmp/media-hygiene
docs_screenshots [fr] # rebuild the image, refresh documentation/ screenshots and console blocks
docs_build / docs_serve  # the documentation site (MkDocs, strict) / preview it on 127.0.0.1:8000
reports / reports_stop  # serve /tmp/media-hygiene/reports on an OS-chosen port
build / dive / dive_ci  # build media-hygiene:latest, inspect, gate the image layers
release               # tag vX.Y.Z from pyproject.toml and push it: CI builds amd64+arm64, e2e, publishes
i18n_update           # after changing any _() string: extract + merge, then translate the .po (i18n_todo lists what is left)
geonames_update       # download GeoNames, rebuild src/media_hygiene/geo/data (offline towns)
ci / ci_logs / ci_watch  # gh: latest CI runs of the branch / logs of the failed steps / follow live (gh auth login once)
git_doctor [--fix]    # after a crash: empty objects in .git/objects, git fsck
docker_doctor / docker_clean  # Docker health, leftovers of e2e/docs runs / remove them
deps                  # direct dependencies with a newer release
```

Without the helpers: `uv run pytest`, `uv run mypy`, `uv run pylint src`,
`pre-commit run --all-files --config .config/.pre-commit-config.yaml`.

## Conventions (enforced by tooling — see `.claude/rules/python.md`)

- Python 3.14, fully typed, mypy strict (+ extra error codes), ruff `select = ["ALL"]`, pylint 10/10.
- **Max 200 lines per file (`src/` only; no cap in `tests/`), max 3 parameters per function** (frozen parameter object otherwise).
  Only documented exception: Typer command functions in `cli/` (one parameter per CLI option).
- Google docstrings everywhere; every CLI command and option has help text.
- Every user-facing string goes through `_()`; run `i18n_update` and translate
  `src/media_hygiene/i18n/locales/fr/LC_MESSAGES/media_hygiene.po` (a test checks completeness).
- Long text (HTML, default `config.toml`) lives in `templates/` directories, never inline.
- Zero junk in the repository: caches go to `/tmp` (env vars in `.devcontainer/Dockerfile`), the
  venv is `/home/vscode/.venv`, hatchling (no egg-info). Tests write only to `tmp_path`.
- Tests: `tests/unit`, `tests/integration` (real files, thread pool instead of process pool),
  `tests/e2e` (marker `e2e`, skipped by default); coverage ≥ 90 % (branches).

## Backlog and Claude tooling

Follow-up work lives in `.todos/NNNN-slug.md` (IDs from `.claude/scripts/todo_next_id.sh`,
header bullets Priority/Batch/Depends/Files, optional Needs maintainer — skill `todo-authoring`).
`/todo:run NNNN` implements, `/todo:plan` regenerates `.todos/plan.md` (never edit it by hand),
`/todo:iterate` asks the blocking questions first, then runs the plan lot by lot in subagents (a
commit per lot, a feedback file to review); `/todo:review-feedback` goes through that file with the
user, applies the decisions and files the follow-ups; `/todo:inbox` gathers everything the backlog
waits for from the maintainer (`.claude/scripts/todo_inbox.py`), asks what can be answered in a
chat and closes, refiles or unblocks the TODOs.
Reviews: `/python-review`, `/bash-review`, `/docker-review`, `/docker-dive-optimization`, agent
`cache-invalidation-reviewer`. Working method (`.claude/rules/workflow.md`, skill
`measure-before-ranking`): the lessons of past sessions. These commands, skills, agents,
rules and scripts are public and shared with the maintainer's other repositories.

`.claude/memory/` (Claude's memory, linked by `.devcontainer/scripts/post-create.sh`) and
`.claude/plans/` are **private**: git-ignored, kept on the host disk so they survive devcontainer
rebuilds, never published. Everything else in `.claude/` is public — keep it free of personal data.
