## Lessons already identified (2026-10-14 sessions), with a proposed home

### A. Recurring mistakes that cost a rerun

1. **`.po` catalog saved with `polib`** re-wrapped the whole file (3,800 lines of diff). *Done
   as a rule* in `.claude/rules/python.md` (2026-10-14); check it is enough, or add a helper
   `i18n_set "<msgid>" "<msgstr>"` that edits the entry in place.
2. **200-line limit met mid-change** (`roster.py` 205, `constants.py` 202, `broken.py` and
   `naming.py` exactly 200): each time a split after the fact. Proposal: a script
   `.claude/scripts/near_limit.sh` listing files ≥ 185 lines among those a TODO's `Files:` names,
   run in `/todo` Phase 1, so the split is planned before writing.
3. **Partial checks before commit**: `mypy` on single files passed, the pre-commit `mypy` (whole
   config) failed on a test's generic typing; pylint caught `missing-return-doc` on a nested
   function and `C1803` (`== []`); ruff `D205` on a two-line test docstring. Proposal: rule
   "before declaring done: `pre-commit run --files <changed>`" (cheap, exactly the gate), plus
   the list of the most frequent pylint/ruff findings in this codebase with their fix.
4. **Tooling surprises**: `pytest -n` does not exist here (no xdist); a foreground `sleep` is
   blocked in the agent; `python -c` with a `ProcessPoolExecutor` needs the `fork` context; the
   scratchpad is not visible to the host Docker daemon (`docker cp` or `-c "$(cat …)"`). Home: a
   short "devcontainer facts" section of the rules, or the measurement skill below.
5. **`.todos/plan.md` regenerated by hand** during `/todo` runs (the command forbids it, but
   invoking `/todo-plan` mid-run reloads a long prompt). Proposal: a deterministic script
   `.claude/scripts/todo_plan_render.sh` (from `todo_parse_backlog.sh`) for the mechanical
   parts (counts, standalone table, PARTIAL list), the judgement (lots) staying in `/todo-plan`.

### B. Design blind spots caught late (by a test or by measuring)

6. **Changing an invalidation rule** (0153: keeping the `stat` of known names hid an edited
   photo; an integration test caught it). Proposal: a checklist rule "when a cache trusts more,
   list every event that used to invalidate it (rename, atomic save, in-place write, copy,
   touch) and test each".
7. **Persisted references by path** (0146: `config.toml` names faces by photo path; `sort`
   moved the rows, not the ids: every name silently lost). Proposal: a rule "anything stored by
   path (index rows, `config.toml`, decisions files, previews) must say what happens when the
   file moves — `sort`, `undo`, a rename in Explorer" and an agent/skill that greps for new
   path-keyed storage in a diff.
8. **Identical copies are ambiguous** (0147: two identical files swapped their rows). Lesson for
   any pairing by content: break ties by name, test with the demo tree's copies.

### C. Measurements and claims

9. **Measure before ranking** worked well (yesterday's guesses were re-ranked by today's
   figures). Make it a skill `measure-on-real-photos`: read-only `--mount …,readonly` of
   `C:\Photos`, `docker run -d` + `docker wait` + `docker logs`, `--cpus 1–2`, cold vs warm
   files (alternate halves), synthetic pictures for CPU costs, `tracemalloc` for memory, one
   step at a time (low machine load), scripts kept in the scratchpad.
10. **Label estimates and unverified claims** in TODOs and summaries (a TODO said "iCloud for
    Windows puts every photo in one folder" without checking; HEIC was measured on non-tiled
    synthetic files). Rule in `todo-authoring`: every figure says *measured* (how, where) or
    *estimated* (from what).
11. **Many TODOs end PARTIAL or BLOCKED for one reason**: a measurement only the maintainer can
    run (Windows + Docker Desktop, GPU, real browser, iPhone files). Proposals: a header field
    `Needs maintainer: <what>` in `todo-authoring`, so `/todo-plan` groups them; and a
    "measurement kit" helper the maintainer runs once that writes all pending figures to one
    file Claude reads (`0104`-style sections, but scripted).

### D. Autonomous runs

12. **The feedback file** of this run (questions, choices, deviations, what waits for the
    maintainer) made the review possible: make it part of `/todo` when several TODOs run
    unattended (template, location `.claude/plans/feedback-<date>.md`, private).
13. **Commit per lot, fsck before commit, no push** worked; write it into `/todo` for
    unattended runs (the memory notes say it, the command does not).
14. **Summaries must state the gains** (where, and how much in %), not only what changed: the
    maintainer asked for it twice. Rule for final reports.
